核心目标
将项目定位为“企业内部后台快速搭建 + 数据大屏”，打通从外部数据库 → 可视化建表 → 表格/表单组件 → 权限控制 → 一键部署的完整链路，让非技术人员能在 10 分钟内生成一个带真实数据的后台页面。

阶段产出
更新后的 README 和官网示例截图

数据源向导（支持 MySQL/PostgreSQL）

增强版表格（排序/筛选/分页/CSV导出/行内编辑）

增强版表单（条件字段/文件上传/富文本）

权限系统（页面+组件级）

一键部署到 OSS/S3

预览模式调试面板

详细任务分解
1.1 更新项目定位与文档（0.5天）
工作项：

修改根目录 README，标题改为“企业级低代码平台 – 快速搭建后台+大屏”

添加功能徽章（数据库集成、一键部署、权限等）

在 docs/ 下新建 SHOWCASE.md，包含两个完整示例的截图和操作步骤

更新 package.json 中的 description 和 homepage

验收：打开项目首页，5分钟内能理解平台核心价值

1.2 数据源向导（3天）
技术方案：

后端：新增 POST /api/datasource/test-connection 测试数据库连通性

后端：新增 GET /api/datasource/tables?dsId=xxx 获取表列表

后端：新增 GET /api/datasource/table-schema?table=xxx 获取字段信息

前端：开发向导 Modal（步骤：选择类型 → 填写连接串 → 测试连接 → 选择表 → 映射字段）

自动生成：基于选择的表生成表格组件的 Schema（列配置、分页、排序）

实现细节：

数据库驱动使用 mysql2 和 pg，连接池管理

连接信息加密存储在 DataSource 表的 config 字段（AES-256）

生成的表格默认绑定 dataSourceId 和 tableName，运行时通过 /api/data-proxy/:dsId/:table 查询

验收：用户输入有效的数据库地址，点击测试显示成功；选择一张订单表后，画布中出现表格并显示真实数据

1.3 增强表格组件（3天）

新增“工具栏”：导出 CSV 按钮、刷新按钮

使用 react-table 或自定义实现排序/筛选逻辑

行内编辑：双击单元格变为输入框，通过事件触发更新（需调用后端更新接口）

与数据源集成：

表格自动接收 dataSource 返回的 list、total、page、pageSize

排序/筛选变化时重新请求数据源（带参数）

验收：在编辑器勾选“允许排序”，预览时点击表头能排序；勾选“允许筛选”，出现筛选输入框；点击“导出 CSV”下载当前页数据

1.5 权限系统基础（2天）
数据模型扩展：

Page 表增加 allowedRoles (JSON, e.g., ["admin", "editor"])

Component 的 props 支持 permissionExpression 字段

后端：

JWT 中携带 role，每个请求 requireAuth 中间件解析到 req.user

页面接口校验 allowedRoles，若不在则返回 403

前端编辑器：

页面设置弹窗增加“允许访问的角色”（多选）

组件属性面板增加“权限表达式”输入框，提供变量提示（如 $user.role）

渲染器：

创建 usePermission Hook，计算当前用户是否有权查看页面/组件

无权组件不渲染（或显示占位提示）

验收：设置页面仅 admin 可见，用 editor 账号登录访问该页面 URL 时被重定向或显示无权限；组件级表达式 $user.role === 'admin' 仅对 admin 显示

1.6 一键部署到对象存储（2天）

验收：点击部署后，生成的文件上传成功，访问返回的 URL 能看到与预览一致的页面

2.6 多人编辑基础（互斥锁）（2天）
后端：

新增表 PageLock：pageId、userId、lockedAt、expireAt

接口 POST /api/pages/:id/lock（返回锁状态）、PUT /api/pages/:id/heartbeat（续期）、DELETE /api/pages/:id/unlock

编辑页面的 PUT /api/pages/:id 先检查锁，无锁或锁过期才允许修改

前端：

进入编辑器时调用 lock，每 30 秒发心跳，页面关闭时发送 unlock

若锁被他人持有，显示只读模式（禁用保存/拖拽/属性修改），并显示“xxx 正在编辑”

验收：两个浏览器登录不同账号，同时打开同一页面，后者看到只读提示；前者关闭页面后，后者刷新可获得编辑权

2.7 版本发布与回滚优化（1.5天）

发布逻辑：点击“发布到生产” → 基于当前 Schema 创建新的 PageVersion（comment="发布"）→ 更新 publishedVersion

回滚逻辑：在版本历史中选择某个历史版本 → 点击“回滚” → 创建新 PageVersion（内容为历史版本的 Schema，comment="回滚至 v3"）→ 编辑器加载该版本

前端：页面管理增加“版本历史”按钮，展示列表，区分生产版本和草稿

验收：修改页面后不发布，访问生产 URL 仍是旧内容；点击回滚后编辑器内容变为旧版本且版本号递增

4.6 性能测试与 Bug 修复（1.5天）
测试场景：

页面含 100 个简单组件（按钮、文本）

页面含 20 个表格组件，每个表格数据源返回 100 行

工具：Lighthouse、React DevTools Profiler

优化目标：

编辑器首屏加载 < 2s（含 Schema 拉取）

画布拖拽帧率 > 50fps

保存操作响应 < 1s

生成代码时间 < 5s（100 组件）
